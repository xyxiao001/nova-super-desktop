# ADR-0006：窗口实例身份与应用实例策略

- 状态：已接受
- 日期：2026-09-02
- 关联 Spec：`docs/specs/SPEC-20260902-window-instances.md`
- 取代：`ADR-0005` 中“暂缓多窗口实例”的决定
- 被取代：无

## 背景

NOVA 的应用接入已经由 Manifest、`AppHost` 和平台 Runtime 统一管理，但 `WindowAppId` 仍同时表示应用类型和唯一窗口。该模型无法表达同一应用的两个窗口，也使窗口标题、焦点、层级、启动目标和工作对象都只能保存一份。

共享 `DesktopItem` 文件模型和贴靠窗口已经提供明确的并行场景：同时浏览两个目录、对照两篇文稿以及比较两张图片。继续保持全局单实例会限制桌面工作流，而让所有应用无条件多开又会增加编辑冲突、资源消耗和应用接入复杂度。

## 决策

### 独立窗口身份

- `WindowAppId` 只表示应用类型；
- 新增 `WindowInstanceId` 表示当前页面会话中的一个运行窗口；
- 焦点、z-index、最小化、最大化、贴靠、标题、关闭通知和启动目标均以实例 ID 为作用域；
- 关闭窗口时销毁实例，最小化时保留实例和组件状态；
- 实例不跨刷新恢复，不进入桌面文件或备份数据。

### Manifest 实例策略

应用通过 Manifest 声明以下策略：

- `singleton`：默认策略，一个应用最多一个实例；
- `multiple`：只通过显式“新建窗口”命令创建额外实例；
- `per-resource`：按 `app + target` 保持唯一实例，重复打开相同资源时聚焦已有窗口。

首批开放范围：

- 文件资源管理器使用 `multiple`；
- 文件夹、记事本和照片查看器使用 `per-resource`；
- 其他应用继续使用 `singleton`。

照片实验室、阅读器和游戏不开放多实例，以避免编辑覆盖、大型内容重复加载和多份游戏运行时。

### 壳层行为

- 任务栏继续按应用分组，实例显示在应用预览中；
- `Alt + Tab` 按窗口实例切换；
- 单例应用及只有一个实例时保持现有任务栏行为；
- 移动端不提供新建窗口入口；打开同类资源时，目标已有实例则聚焦该实例，否则复用当前应用实例；
- 页面从桌面宽度缩小到紧凑视口时保留已有实例，但同时只显示聚焦的全屏实例。

### 数据边界

- 桌面文件继续由 `WorkspaceRuntime` 统一管理并持久化到 IndexedDB `nova-desktop`；
- 资源目标属于窗口实例，不复制 `DesktopItem` 内容；
- 窗口几何继续以应用级 localStorage 记录作为新实例模板，不为临时实例创建永久键；
- 不修改备份格式、Storage Provider、Service Worker 或资源包协议。

## 备选方案

### 继续保持应用级单实例

- 优点：实现简单，现有窗口和应用状态无需迁移；
- 缺点：无法形成目录整理、文稿对照和图片比较等桌面工作流；
- 未选择原因：明确的并行工作对象场景已经出现，满足 `ADR-0005` 的重新决策条件。

### 所有应用默认支持多实例

- 优点：规则表面统一，应用可以自由多开；
- 缺点：会让设置、阅读器、编辑器和游戏承担无意义或高成本的重复实例，并引入存档和覆盖冲突；
- 未选择原因：多实例必须由产品场景驱动，默认开放会扩大风险和资源占用。

### 每个实例占用独立任务栏图标

- 优点：窗口与图标一一对应，实现直接；
- 缺点：固定应用与运行窗口混在同一层，多个同类窗口会挤压任务栏；
- 未选择原因：按应用分组更符合现有任务栏信息架构，也保留固定应用入口。

### 持久化并恢复窗口实例

- 优点：刷新后可以恢复工作现场；
- 缺点：改变当前“刷新只恢复文件、不自动打开应用”的产品边界，并需要处理失效资源和版本迁移；
- 未选择原因：本阶段只解决同一页面会话内的并行工作，不扩展启动生命周期。

## 影响

### 正向影响

- 同一应用可以承载多个独立工作对象；
- 贴靠布局、任务栏预览和 `Alt + Tab` 获得实例级语义；
- 应用是否允许多实例由统一 Manifest 决定；
- 同一资源去重规则集中在窗口 Runtime，不散落到应用组件。

### 代价与限制

- 窗口 reducer、Runtime、宿主、任务栏和跨应用启动都需要从应用 ID 迁移到实例 ID；
- 文件夹、记事本和照片查看器需要将当前资源从全局状态迁移到实例目标；
- 应用内部资源切换必须协调当前实例与目标资源已有实例；
- 多个应用组件同时挂载会增加内存占用，因此多实例范围保持显式且有限。

### 对现有能力的影响

- 数据与迁移：不修改用户数据结构，无数据迁移；
- 应用接入：新应用默认单例，只有明确场景时才声明其他策略；
- 测试：增加实例 reducer、资源去重、任务栏分组、文件生命周期和移动端行为测试；
- 构建与部署：不新增依赖、资源或构建步骤。

## 实施边界

- 本决策要求修改：窗口身份和生命周期、Manifest 窗口策略、实例宿主、实例级启动目标、任务栏分组及首批四类应用的工作对象归属；
- 本决策不要求修改：桌面文件结构、备份版本、资源缓存、Storage Provider、应用视觉、外部资源托管或跨窗口拖放。

## 验证方式

- 所有应用保持单例时，现有窗口操作测试继续通过；
- 同一应用多个实例可独立聚焦、最小化、最大化、贴靠和关闭；
- 相同资源重复打开只聚焦已有实例；
- 任务栏按应用分组，`Alt + Tab` 按实例切换；
- 删除绑定资源只关闭受影响实例；
- 紧凑视口不主动创建并行实例；
- 刷新后不恢复窗口，用户数据保持不变。

## 后续决策

- 跨窗口拖放、照片实验室多实例和会话恢复必须分别形成新的产品目标与 Spec；
- `ADR-0005` 关于大型资源继续同源托管的决定保持有效。

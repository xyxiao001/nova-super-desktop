# ADR-0002：以 Storage Provider 统一用户数据生命周期

- 状态：已接受
- 日期：2026-08-28
- 关联 Spec：`docs/specs/SPEC-20260828-p1-storage-providers.md`
- 取代：无
- 被取代：无

## 背景

本地数据统计、清理和备份分别维护数据清单，已经导致魔塔数据可清理但不可备份。后续新增应用存储会继续放大遗漏风险。

## 决策

每个用户数据分类通过本地 Storage Provider 声明检查、导出、验证、恢复和清理生命周期。设置页和备份系统只遍历 Provider 注册表，不再各自识别应用数据。备份格式升级为 v2 Provider 数据，并保留 v1 的确定性导入规范化。

## 备选方案

### 继续维护两套集中清单

- 优点：短期改动少；
- 缺点：新增数据需要同步修改统计、清理和备份；
- 未选择原因：现有魔塔遗漏已经证明该方式无法维持一致性。

### 每个应用直接操作设置页和备份

- 优点：应用完全负责自身数据；
- 缺点：系统 UI 与应用组件耦合，难以统一验证；
- 未选择原因：生命周期契约应独立于应用窗口是否加载。

## 影响

### 正向影响

- 同一数据声明覆盖统计、备份、恢复和清理；
- 魔塔和后续特殊 IndexedDB 可以被完整管理；
- 旧 v1 备份保持可导入。

### 代价与限制

- 跨 Provider 恢复仍不具备全局事务；
- 新 v2 备份不能由升级前的旧代码导入。

### 对现有能力的影响

- 数据与迁移：设备数据不迁移，备份文件格式升级；
- 应用接入：新增持久化数据时必须注册或扩展 Provider；
- 测试：Provider 必须覆盖完整生命周期；
- 构建与部署：无变化。

## 实施边界

- 本决策要求修改：本地数据统计、清理、备份和恢复编排；
- 本决策不要求修改：应用写入方式、存储 key、数据库结构或 UI 流程。

## 验证方式

- Provider、v1/v2 备份和 fake IndexedDB 生命周期单测。

## 后续决策

- 是否将游戏数据迁移到 IndexedDB 由独立 Spec 决定。

# ADR-0007：系统级 AI 连接使用独立本地存储边界

- 状态：已接受
- 日期：2026-09-03
- 关联 Spec：`docs/specs/SPEC-20260903-desktop-pet-system.md`
- 取代：无
- 被取代：无

## 背景

桌面宠物后续需要使用用户自行提供的 AI 请求地址、模型名称和 API Key。NOVA 已有的 Storage Provider 会统一参与统计、普通备份、恢复和分类清理，但 AI Key 明确不能进入备份、localStorage、日志、事件或 Service Worker 缓存。多套配置还必须保持地址、模型与 Key 的组合关系，不能在切换时跨配置拼接。

## 决策

系统层使用独立 IndexedDB 数据库 `nova-ai-connections` 保存连接档案和 AI 设置。连接档案包含固定协议、请求地址、模型名称和 API Key；设置记录包含启用状态、唯一当前连接 ID 和上下文权限。

该数据库不注册 Storage Provider，不参与普通 NOVA 备份。设置应用通过专用仓储 API 新增、编辑、删除、切换和清空配置；列表只读取 Key 末四位，只有未来的 AI 适配器可以通过当前连接读取完整档案。删除当前配置时只把当前连接置空，不选择其他配置；任何失败都不触发重试或配置切换。

OpenAI-compatible 适配器直接使用档案中的完整请求地址，并在单次请求中成组使用该档案的模型和 Key。会话 ID 在内存中生成，不持久化；请求显式使用 `no-store`，失败后不读取其他档案。

## 备选方案

### 复用 `nova-settings` localStorage

- 优点：实现简单；
- 缺点：Key 会进入普通设置备份，并扩大同步、日志和调试暴露面；
- 未选择原因：违反敏感连接配置的隔离要求。

### 注册独立 Storage Provider

- 优点：可以复用统一统计和清理入口；
- 缺点：Provider 契约默认包含导出和恢复，容易让 Key 进入普通备份；
- 未选择原因：AI 配置需要明确排除于常规数据生命周期。

### 只保存一套活动配置

- 优点：数据结构最小；
- 缺点：切换服务时需要覆盖字段，不能保持成组配置；
- 未选择原因：不满足多配置整体切换和手动选择要求。

## 影响

### 正向影响

- AI 凭据与普通用户数据、备份和缓存明确隔离；
- 多套配置以完整档案切换，不存在跨配置组合；
- 删除与失败行为具备确定性，不会静默选择备用配置。

### 代价与限制

- 浏览器 IndexedDB 不是硬件密钥保护，同源脚本和本机浏览器访问者仍可能读取 Key；
- 配置不会跨浏览器、设备或备份恢复；
- “重置 NOVA”需要显式调用专用清理 API 才能删除 AI 配置。

### 对现有能力的影响

- 数据与迁移：新增独立数据库，无旧数据迁移；
- 应用接入：设置应用使用摘要读取，未来 AI 适配器使用活动配置读取；
- 测试：覆盖成组保存、手动选择、删除当前项和隔离边界；
- 构建与部署：无变化。

## 实施边界

- 本决策要求修改：AI 连接仓储、设置页连接管理和全量重置调用；
- 本决策不要求修改：普通备份格式、Storage Provider 注册表、Service Worker、宠物数据和 AI 请求实现。

## 验证方式

- 使用 fake IndexedDB 验证多配置 CRUD、设置恢复、删除当前配置与全量清理；
- 静态验证数据库未注册到普通备份和 Service Worker。

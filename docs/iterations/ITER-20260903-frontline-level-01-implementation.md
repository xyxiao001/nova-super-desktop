# 前线第一关战斗实现

- 日期：2026-09-03，2026-09-04 更新
- 状态：限定功能切片已实现，整关 1:1 复刻仍未验收
- 对应 Spec：`SPEC-20260903-frontline-faithful-battle.md`
- 关卡：`100101` / `desert-1` / `烈日沙漠1`

## 本轮目标

以第一关资源审计结果为唯一输入，替换旧的静态原型，建立后续关卡可复用的固定步长战斗核心、WebGL Spine 渲染层和 React HUD 边界。本轮额外完成用户限定的 4 英雄、沙王领主和简易英雄招募闭环。

## 已实现

- 从 `LevelAssetManifest` 加载 12 个路径点、12 个塔位、4 名账号英雄、沙王和 6 波 18 个刷怪组；
- 使用固定 60Hz 模拟，RAF 只负责累积时间和渲染，React 每约 100ms 接收一次 HUD 快照；
- 页面隐藏、暂停和结算状态不补算战斗时间，支持一倍速与二倍速；
- 怪物按真实路径弧长移动，到达终点后按配置扣除水晶生命；
- 敌人按当前路径段水平切线左右翻面，转弯后头部保持朝向行进方向；
- 沙王从战斗开始常驻 `playerSlot`，4 名编队英雄不再自动部署；
- “召唤”按 `10 / 20 / 30 / 45 / 60 / 80 / 90...` 递增扣除银币，从当前编队选择英雄并放入空塔位；
- 第 5 次召唤后开放“强化”，费用读取原配置；同强化等级下已有和后召唤单位使用一致倍率；
- 击杀按配置增加银币，沙王和每个上场英雄分别累计实际伤害；
- 怪物使用 `MonsterLevelProp_C.lHP` 基础生命和六波 `monsterPropRatios` 倍率；
- 英雄按账号攻击、原技能伤害系数、冷却、范围和已确认事件帧选择最前目标；
- 使用 900x1600 逻辑坐标和原版第一关地图、部署石台、BGM；
- WebGL 加载并逐帧渲染 4 名真实英雄、沙王和 3 类怪物的 Spine 4.2.33 资源；
- 单位按脚底纵坐标排序，2D overlay 绘制怪物生命条；
- 提供波次、剩余敌人、水晶生命、银币、召唤、强化、战斗时间、暂停、倍速、统计和胜负返回；
- 英雄页使用原版城堡/布阵底图与 4 名英雄真实 Spine `stand`，支持查看、材料升级和最多 4 人编队；
- 队伍编辑使用独立布阵层和草稿阵容，关闭放弃修改，保存后写入本地存档；
- 英雄详情使用全屏结构、动画角色和左右切换；领主页展示沙王、六件装备、背包和升级入口；
- 招募页支持单抽/十连、结果弹窗、券/进度/英雄碎片更新并写入本地存档；
- 第一章地图使用原 `Main_background_01`、主线节点和当前节点提示，保留账号资源栏、“最新章节”及招募入口；
- `1-1` 挑战面板展示四英雄 Spine 编队、三星条件、三种真实怪物头像和奖励预览；
- 挑战面板“布阵”直达独立布阵层，“出战”进入现有第一关资源加载流程；
- 结算成功后才写入第一关星级与最佳水晶生命存档；
- 独立回归入口为 `/frontline-battle`，不依赖桌面窗口操作。

## 本轮修正

`EctypeWave.waitTimeMs=0` 表示禁用最大等待时间。战斗核心曾把零值当成已超时，
导致第一波最后一只怪生成后立即切波；现已改为仅在等待时间大于零时启用超时分支，
并增加固定 60Hz 回归用例。

连续强化曾让已有单位按 `1.1` 连乘、后召唤单位按等级线性计算，二级起伤害不一致；
现统一按强化等级换算倍率，并增加先强化再召唤的缺陷回归用例。

英雄 Spine 的 `default` 皮肤只包含脚底阴影。英雄主页、详情、布阵和战斗现统一切换到
普通外观皮肤 `01`，资源加载、皮肤选择和纹理释放由共享模块管理。

英雄主页完成第二轮实机像素对照。顶部资源栏不再使用 CSS 图形模拟，改为固定 Bundle
中的 `Icon_item_zuanshi`、`Icon_item_jinbi`、`Icon_item_tili`、
`Common_huobi_di` 和 `Common_jiahao`；英雄卡改用 163x207 的
`Common_kapai_cheng`、四张 `lihui_*` 全身立绘、职业角标、出战条、等级盾和碎片条。
以微信小游戏可见内容和本地最大化窗口按相同比例并排复核后，校准了资源槽尺寸与间距、
图标边界、首行卡片位置、立绘基线和卡片附属元素。英雄页资源契约现固定为 10 个
Bundle、62 个输出文件，来源与 SHA-256 记录在 `HERO_UI.md` 和
`ui/heroes/source-manifest.json`。

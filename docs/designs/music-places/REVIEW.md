# 听歌场景设计自审 · 2026-09-29

设计稿：[index.html](index.html)。四张 1000×560 原生矢量构图已在 Chromium 渲染并逐张查看，设计先于业务代码。

## 判断

- 海上列车：暖色横向分层与车厢前景成立；保留太阳在右、文字在左，海面不加常规频谱柱。实现时增加水面碎光与远岛的层次，避免像一张平面壁纸。
- 雨巷咖啡：深青暗面与右侧琥珀光形成明确冷暖关系，玻璃细雨与杯子给出尺度。实现时让雨滴有折射感，左侧保持干净，蒸汽限制在杯子上方。
- 黑胶档案：唯一明亮场景，书页式排字与斜俯视物件能明确区分。实现时使用真实厚度、沟槽、金属唱臂和物件投影，不能变成一个悬空圆盘。
- 月面电台：纵深及留白与前三者不同。实现时补地表起伏、陨坑和天线支架，星点保持克制；避免复用演唱会光束或紫色星云。

## 实现约束

1. 新场景不共用城市天际线、中央大字或整屏色相滤镜。只共用渲染生命周期与歌词数据。
2. 近景/中景/远景按场景命名，夜场仍用前排/看台/全景。色调只调整局部光色，保留每个场景的基础材质。
3. 窄屏重新定位歌词和主体：列车保留单窗；咖啡将杯子放到右下；唱机移到下半部；地球与天线向右下移动。
4. 真实歌词可能远长于示意稿，正文允许换行，使用受控字号和容器尺寸；不裁切歌词，也不把长歌名压在主体上。
5. 暂停、减少动态、隐藏窗口时停止动画；切换和关闭后释放 WebGL 资源。

结论：通过方向评审，按以上四项修正进入代码实现。最终还需用真实组件检查桌面与窄屏，而不是仅以设计稿代替验收。

## 实现后复核

- 使用实际组件的 1440px 桌面和 390px 手机截图复核四个场景。
- 已修正首版月面地平线过高、地球裁切及暖色照明问题；月面和天线使用独立冷色照明。
- 黑胶沟槽改为带导数抗锯齿的程序材质，移除密集几何圆环引起的摩尔纹。
- 手机列车太阳下移至海平面附近，避开歌词；月面地球与天线错开。
- 以带电影说明和歌手信息的长歌名检查手机排版，修正唱片和月面容器规则的优先级；全文显示，文字不压住唱机或地球。
- 暂停、减少动态和最小化后，浏览器 WebGL 绘制计数停止；恢复播放后继续绘制。
- 地点选择器只有五项，夜场演唱会组件与 concert.css 没有差异。

结论：实现后视觉与交互验收通过。

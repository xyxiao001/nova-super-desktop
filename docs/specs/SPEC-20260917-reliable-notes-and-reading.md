# SPEC-20260917：可靠记事与阅读摘录回链

- 状态：已完成
- 提出日期：2026-09-17
- 相关 ADR：按第二轮实际数据设计补充
- 相关迭代：`docs/iterations/ITER-20260917-reliable-notes-01.md`、`docs/iterations/ITER-20260917-reader-backlinks-02.md`

## 背景与现状证据

- `src/apps/notes/entry.tsx` 固定显示“已自动保存”，但 `src/shell/DesktopRoot.tsx` 通过 `createDesktopSyncQueue` 异步写入，失败时仅有短时 Toast。
- `app/desktopStorage.ts` 已将元数据与 Blob 正文分开，增量队列仅在事务成功后更新已提交快照。
- `src/apps/reader/readerCore.ts` 将摘录格式化为普通文本，来源仅有书名和章节名，没有可跳转的结构化位置。
- 桌面已经具备多实例文稿、共享工作区和跨应用启动协议，不重复建设这些能力。

## 目标

让记事本如实显示当前文稿的持久化状态，并让新建阅读摘录可以回到对应原文位置。按两个有终点的单目标迭代执行，不设置定时任务或无人值守循环。

## 非目标与不修改边界

- 不增加账号、云同步、遥测、后台任务、自动重试或 AI 请求。
- 不新增文件类型、第二套正文存储或工具私有文件副本。
- 不自动打开刷新前窗口；不改变关闭、最小化、最大化语义。
- 不改照片、游戏、宠物、主题、资源包和部署策略。
- 不自动构建、提交、推送或发布；不操作真实用户的文件、存档或浏览器数据。
- 搜索直达、Markdown、批量图片、主题工作集和任务内 AI 均不在本批实现范围。

## 方案

### 迭代一：真实保存状态

- 记事本按当前文稿快照显示“保存中…”、“已保存到本机”或“保存失败”。
- 以现有写入队列成功提交的快照为准，旧写入完成不能将更新的文稿错误标为已保存。
- 保存失败后保留当前内存中的正文，并提供用户主动下载当前 TXT 的入口；不回滚、不清空、不另存缓存、不自动重试。
- 状态同时覆盖文件名和正文；多个文稿的状态按各自当前内容判定。
- 保存反馈在紧凑布局中同样可见，不依赖瞬时 Toast。

### 迭代二：摘录回链

- 新摘录仍是桌面文本，增加可选来源元数据，关联书籍、章节和正文位置。
- 记事本提供“返回原文”，由现有启动协议打开阅读器并定位。
- 已有普通文稿与旧摘录保持原样，不从文本猜测来源、不做历史回填。
- 来源书籍或位置不可用时明确提示，不联网自动下载、不覆盖当前阅读进度或丢弃摘录。
- 来源元数据与桌面文件一同持久化、复制、备份、恢复和清理，不另建正文仓库。

## 平台影响

- 保存队列与 WorkspaceRuntime：增加持久化状态的只读呈现，不改变写入时机。
- 记事本：保存状态、失败导出、来源入口；保持现有编辑和窗口结构。
- 文件元数据与备份：第二轮只增加可选摘录来源，需验证往返和普通文件兼容。
- 阅读器与 LaunchRuntime：第二轮增加定位意图，保持普通打开书籍行为。
- Service Worker、资源包、应用注册、构建部署：不修改。

## 验收标准

- [x] AC-1：写入事务完成前显示保存中，完成后才显示已保存。
- [x] AC-2：快速连续编辑时，旧快照成功不把最新内容误标已保存；其他未变文稿保持准确状态。
- [x] AC-3：写入失败显示失败并保留内容，手动导出入口可用，不产生自动重试。
- [x] AC-4：新摘录携带准确来源，记事本可回到选区起始位置。
- [x] AC-5：缺失来源或位置失效时给出提示，旧摘录和普通文稿正常编辑。
- [x] AC-6：来源经过增量保存、复制、备份恢复仍保留，删除按现有文件生命周期处理。
- [x] AC-7：TypeScript、直接相关单测、最短关键路径与 diff 审查通过。

## 验证计划

- 类型检查：`npx tsc --noEmit --incremental false`，不产生 tsbuildinfo。
- 单测：按当前迭代仅运行存储队列、记事本、摘录、启动与备份直接相关测试。
- 浏览器：使用隔离的测试入口/浏览器来源验证新文稿编辑、摘录与回链，不修改用户原有数据。
- 不运行 lint 或完整构建；未覆盖的真实环境异常在记录中明确说明。

## 风险与迁移

- 并发写入必须区分当前内容与已提交快照，不以单一全局成功布尔值代替。
- 摘录位置可能因书籍删除或内容变化失效，失败时不得静默跳转到无关位置。
- 第二轮如发现必须改数据库结构、备份版本或新增兼容逻辑超出本规格，应记录阻塞而非静默扩大范围。

## 确认记录

- 2026-09-17：用户在上述能力建议后明确授权规划并进行自动化迭代；本批采用其中真实保存状态与阅读摘录回链，其他方向留后续，不视为无限授权。

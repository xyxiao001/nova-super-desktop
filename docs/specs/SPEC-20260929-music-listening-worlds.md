# SPEC-20260929：可分享的私人音乐演出

- 状态：已完成（导演台按用户后续要求移除）
- 提出日期：2026-09-29
- 确认：用户要求“分享的时候，这种播放舞台也能一起分享”，并明确同意开始实现上一轮讨论的场景、音效、演出标记和歌单演出。

## 目标

让个人音乐 App 的舞台成为可保存、可分享的听歌场景。保持原有本地优先和公共曲库分享方式。

## 分轮范围与验收

1. 舞台分享：歌曲链接携带场景、机位与配色；打开链接恢复同样的视觉演出。普通歌曲分享保持原语义，私人音频不上传。
2. 听歌地点：夜场、深夜列车、雨天房间、天台夜景、黑胶听音室、宇宙漂流，歌词融入各场景；暂停/减少动态效果时停止连续运动。
3. 场馆音效：原声、Livehouse、音乐厅、复古电台、深夜聆听，用户主动选择；雨声单独开关和音量，不随分享链接自动启用声音处理。
4. 舞台布局：按用户后续要求移除导演台、事件记录与重演逻辑。舞台占据主要区域，场景与机位常驻控制栏，灯色、音效、雨声和保存入口收进氛围设置；移除重复歌曲信息，底部保留播放器。
5. 歌单演出：命名、排序、开场/主场/安可角色、开场及谢幕画面、曲目衔接方式和本地票根。演出只在用户启动后运行。

## 数据与接入

歌曲演出配置作为音乐 Track 的可选 `performance` 内容存入现有 nova-music；未保存场景的歌曲从夜场看台开始。歌单的演出设置作为 Playlist 可选 `show` 内容。现有备份恢复按对象结构包含这些数据，清理音乐同时移除。不会增加第二份库、后台同步或新数据库。

分享只通过现有公共 catalog ID 查找音频，URL fragment 携带视觉配置，不上传本地音频、API Key、个人听歌记录或整份音乐库。链接导入配置先作为当前演出草稿，用户点击保存后才写入歌曲。

## 修改范围

音乐应用 entry、sharing、ConcertStage、model、usePlayer，以及新增听歌场景、氛围设置、音效、歌单演出组件/样式和相关单测。按现有 Storage Provider 路径核对备份与清理。不改桌面外壳、窗口契约、下载时机、自动歌词搜索、Service Worker 或现有错误处理策略。

## 不修改边界

不加入云存储、账号、第三方素材、AI 自动副歌识别、人声分离、真实多轨空间音频或额外上游服务。不新增兜底、自动重试、迁移或额外提交校验。不自动提交、推送或发布。

## 验证

每轮 TypeScript 与直接相关单测；浏览器沿一条歌曲播放/分享/场景设置路径验证，窄屏检查；不运行 lint 或完整构建。有限效果路径及节拍视觉不声称识别真实乐器；合成混响只模拟空间听感。

# SPEC-20260902：资源管理器跨窗口拖放

- 状态：已完成
- 提出日期：2026-09-02
- 负责人：Codex
- 相关 ADR：无
- 相关迭代：`docs/iterations/ITER-20260902-explorer-window-drag-drop-01.md`

## 背景

窗口实例化完成后，用户可以把两个资源管理器窗口并排打开，但跨窗口整理文件尚未形成明确契约和浏览器验收。资源管理器已有内部拖放事件和统一文件操作入口，当前缺口是把拖放载荷、复制修饰键与跨实例行为固化为共享协议和回归测试。

## 目标

允许用户把一个资源管理器窗口中的文件或文件夹拖到另一个资源管理器窗口：默认移动，按住复制修饰键时复制，并继续使用现有重名冲突弹窗和单步撤销记录。

## 非目标

- 不支持拖入记事本、照片实验室、任务栏图标或其他应用；
- 不新增跨窗口拖放队列、拖放历史面板或后台任务；
- 不改变移动、复制、重名冲突和撤销的数据算法；
- 不为触控设备新增拖放手势。

## 当前行为

- 资源管理器项目使用 `application/x-nova-desktop-items` 写入项目 ID；
- 资源管理器内容区和文件夹项目会把拖放交给 Workspace Runtime 的统一文件操作；
- 桌面与资源管理器分别实现了载荷解析和修饰键判断；
- 现有单测覆盖文件操作结果，但未锁定共享拖放协议和跨窗口交互。

## 方案

### 用户可感知行为

- 拖到另一个资源管理器窗口的空白区域时，项目进入该窗口当前文件夹；
- 拖到另一个窗口中的文件夹项目时，项目进入该文件夹；
- 默认执行移动；按住 `Ctrl`、`Command` 或 `Option` 时执行复制；
- 遇到同名项目时继续显示现有“替换 / 保留两份 / 取消”弹窗；
- 成功操作继续生成一条现有文件撤销记录。

### 技术设计

- 在 `app/desktopFiles.ts` 提供共享拖放载荷读写和操作模式解析；
- 桌面与资源管理器统一使用共享函数，避免不同落点产生不同语义；
- 跨窗口仍通过浏览器原生 `DataTransfer` 和 Workspace Runtime 完成，不增加窗口间状态通道。

### 数据与状态归属

- 数据所有者：`DesktopRoot` 中的统一 `DesktopItem[]`；
- 状态生命周期：拖放载荷仅存在于单次浏览器拖放会话；
- 持久化位置：沿用 IndexedDB `nova-desktop`；
- 是否需要迁移：否。

## 修改范围

### 计划修改

- `app/desktopFiles.ts`：共享拖放载荷和操作模式；
- `src/apps/explorer/entry.tsx`：使用共享拖放协议；
- `src/shell/DesktopRoot.tsx`、`src/shell/DesktopIcons.tsx`：桌面拖放入口使用同一协议；
- `tests/unit/desktopFiles.test.ts`：覆盖载荷解析与复制修饰键；
- `README.md`：补充跨资源管理器窗口拖放说明；
- 对应 Spec 与迭代记录。

### 不修改边界

- 保持 `DesktopItem`、IndexedDB 和备份格式不变；
- 保持现有冲突弹窗、替换、保留两份和撤销行为不变；
- 保持移动端禁用项目拖放；
- 不新增兜底、自动重试或兼容分支；
- 不修改其他应用的拖放处理。

## 验收标准

- [x] AC-1：给定两个资源管理器窗口，当项目拖到另一窗口当前文件夹的空白区域时，默认移动到目标文件夹；
- [x] AC-2：给定目标窗口中存在文件夹，当项目拖到该文件夹时，移动到该文件夹；
- [x] AC-3：给定拖放时按住复制修饰键，当落入另一窗口时，源项目保留且目标位置生成副本；
- [x] AC-4：给定目标位置存在同名项目，当跨窗口拖放时，继续使用现有冲突弹窗及三种处理策略；
- [x] AC-5：给定跨窗口移动或复制成功，当执行撤销时，恢复操作前的文件树；
- [x] AC-6：TypeScript、相关单测、diff 审计和桌面浏览器关键路径通过。

## 验证计划

- TypeScript：`npx tsc --noEmit`
- 相关单测：`tests/unit/desktopFiles.test.ts`、`tests/unit/appComponents.test.ts`、`tests/unit/desktopIconInteraction.test.ts`、`tests/unit/shellArchitecture.test.ts`
- 关键交互：两个资源管理器左右贴靠，从源文件夹拖到目标窗口空白区域和子文件夹，验证移动、冲突弹窗和撤销；复制修饰键由纯函数单测覆盖；
- 不执行的验证及原因：不运行 lint 或完整构建；移动端拖放不在范围内。

## 风险与迁移

- 已知风险：浏览器在拖放期间对修饰键的上报存在平台差异，因此统一接受 `Ctrl`、`Command` 和 `Option`；
- 数据迁移：无；
- 回滚方式：恢复桌面和资源管理器内原有的局部载荷解析。

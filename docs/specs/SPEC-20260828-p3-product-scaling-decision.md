# SPEC-20260828：P3 多窗口实例与大型资源托管决策

- 状态：已完成（决策）
- 提出日期：2026-08-28
- 负责人：Codex
- 相关 ADR：`docs/adrs/ADR-0005-defer-multi-instance-external-assets.md`

## 观察

- 当前窗口状态、Runtime、任务栏和几何配置均以 `WindowAppId` 为唯一键，产品行为是每个应用一个运行实例；
- 应用内部状态也按单例设计，尚无“同时编辑两个文稿/浏览两个目录”的明确产品入口；
- 本地大型资源约为：魔塔 85 MB、书籍 27 MB、Stockfish 7 MB、照片 3.7 MB；
- P2 已把这些资源从启动壳排除，并按资源包按需缓存和独立清理。

## 决策

### 多窗口实例

当前不实现。继续使用单应用单实例，直到产品路线明确需要并行文档、并行目录或多局游戏。届时需要以 `WindowInstanceId` 作为会话主键，并同时设计实例级标题、Dock 分组、几何持久化、关闭语义和应用状态归属，不能只把窗口数组化。

### 独立大型资源托管

当前不迁移到独立域名或外部服务。继续使用同源静态资源 + 独立资源包，因为它符合本地优先、Service Worker 离线和用户主动打开后加载的产品边界。Manifest 已提供资源包与应用关联，可在部署体积、发布频率或团队所有权实际要求解耦时扩展托管地址。

## 不修改边界

- 不改变现有单实例窗口能力；
- 不新增账号、云服务、跨域 CDN、后台下载或资源镜像；
- 不改变资源 URL、缓存策略和离线行为；
- 不为尚未确定的能力预埋运行时兼容分支。

## 重新决策触发条件

- 产品明确要求同一应用同时打开两个独立工作对象；
- 大型资源需要与桌面壳独立发布或由不同团队维护；
- 目标部署平台的制品限制、上传时长或发布回滚已成为可复现阻塞；
- 同源托管无法满足明确的区域、成本或带宽目标。

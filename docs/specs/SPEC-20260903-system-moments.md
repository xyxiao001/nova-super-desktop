# SPEC-20260903：系统性彩蛋与庆祝反馈

- 状态：已完成
- 提出日期：2026-09-03
- 负责人：Codex
- 相关 ADR：无
- 相关迭代：`docs/iterations/ITER-20260903-system-moments-01.md`
- 依赖 Spec：`SPEC-20260903-desktop-creative-objects.md`（仅后续纪念物能力依赖；首版视觉反馈不依赖）

## 背景

NOVA 已经在窗口、文件和部分游戏中提供操作音效，也保存游戏战绩、专注记录、阅读进度和桌面文件。当前反馈主要局限在各应用内部：一次创作保存、一次专注完成或一局游戏胜利不会在桌面系统层产生共同响应。

对于单人使用的个人桌面，彩蛋的价值不是促进签到或提高留存，而是让系统对真实使用行为表现出轻微、偶发且可辨认的回应。彩蛋需要保持克制，不能遮挡操作、制造持续通知或演变为任务和奖励体系。

## 目标

建立一套最小的系统时刻事件与桌面效果层：照片或画板创作保存完成、专注计时完成、棋类或扫雷胜利时，应用发布明确事件，桌面显示与事件类型对应的一次性视觉反馈；反馈不持久化、不阻断交互，并尊重减少动态效果设置。

## 非目标

- 本次不实现每日签到、连续天数、等级、经验、全局成就或彩蛋图鉴。
- 本次不奖励大厅金币，不改变任何游戏概率、难度、结算或存档。
- 本次不新增系统通知、浏览器通知、后台任务、定时唤醒或自动打开窗口。
- 本次不实现节日、生日、纪念日等日期型彩蛋。
- 本次不生成永久桌面纪念物；该能力待桌面物件模型稳定后另行确认。
- 本次不增加联网请求、远端配置、在线素材或音频文件。
- 本次不改变应用原有成功判定、保存时机、提交参数和异常处理。

## 当前行为

- `playNovaSound` 提供打开、关闭、移动、成功和错误五类即时合成音效，是否播放由现有设置控制。
- 桌面通过 Toast 和文件活动通知反馈部分文件操作，但没有全屏或跨窗口的庆祝效果层。
- 游戏记录由游戏共享存储记录，但各游戏负责自己的胜负判定和界面。
- 专注时钟在应用内部维护计时和历史记录。
- 照片实验室和画板通过现有工作区能力生成或更新桌面图片。
- 现有动画已经在相关样式中使用 `prefers-reduced-motion` 关闭或简化。

## 方案

### 用户可感知行为

- 照片实验室或画板成功生成新的桌面图片后，桌面边缘出现一次轻量星光扩散，持续不超过 1.8 秒。
- 一次专注倒计时自然完成后，桌面出现一次暖色呼吸光环，持续不超过 2.4 秒。
- 扫雷、国际象棋或五子棋明确判定用户胜利后，当前窗口周围出现一次纸屑/火花效果，持续不超过 2.4 秒。
- 彩蛋层不接收指针事件，不改变焦点，不暂停应用，不打开面板，也不要求用户关闭。
- 同一时刻只显示一个系统彩蛋；新事件到达时替换当前效果，不排队播放。
- 当系统启用 `prefers-reduced-motion: reduce` 时，不播放位移动画，改为不超过 600 毫秒的静态光晕淡入淡出。
- 系统音效关闭时彩蛋保持静音；系统音效开启时复用现有 `success` 合成音效，不新增独立音频资源。
- 彩蛋不会写入记录，刷新页面后不存在“未播放彩蛋”或补播行为。

### 首版事件范围

| 事件 | 发布条件 | 不发布条件 | 桌面效果 |
| --- | --- | --- | --- |
| `creative-save` | 照片实验室另存为新图片成功；画板保存为新图片成功 | 覆盖已有图片、保存失败、取消保存 | 桌面边缘星光扩散 |
| `focus-complete` | 专注模式倒计时自然归零并完成记录 | 手动停止、重置、普通倒计时、秒表和计次 | 暖色呼吸光环 |
| `game-win` | 扫雷、国际象棋或五子棋现有规则明确记录用户胜利 | 失败、和棋、重新开始、载入存档 | 当前窗口周围纸屑/火花 |

魔塔、YouTD 2 和童年老虎机首版不接入：三者的阶段胜利、结算和 iframe/桥接边界不同，应在后续按各自明确事件单独评估，不能推断为普通 `game-win`。

### 技术设计

- 新增封闭的系统时刻事件类型 `NovaSystemMoment`，首版只允许 `creative-save`、`focus-complete` 和 `game-win`。
- 提供进程内发布与订阅函数，使用浏览器 `CustomEvent` 传递事件；不建立队列、不持久化、不自动重试。
- 事件只携带效果选择所需的类型、来源应用 ID 和唯一触发 ID，不传递图片内容、文稿内容、游戏棋盘或用户数据。
- `DesktopRoot` 订阅系统时刻，并把当前事件交给独立的桌面效果层渲染。
- 效果层位于窗口与桌面视觉环境之上、系统菜单和任务栏交互之下，使用 `pointer-events: none`，不参与窗口焦点和键盘处理。
- 当前效果通过一次性定时器清除；收到新事件时清除上一效果并立即显示新效果。
- 各来源应用只在现有成功分支的末尾发布事件，不增加二次成功校验或新的异常处理。
- 游戏接入沿用各自已经产生的用户胜利结果，不从共享战绩变化反向推断，以免其他窗口或恢复数据误触发。
- 视觉元素优先使用 CSS 伪元素和文字符号，不新增图片、SVG、Canvas 引擎或第三方粒子库。

### 数据与状态归属

- 数据所有者：无持久化所有者；事件属于当前页面会话中的瞬时系统反馈。
- 状态生命周期：来源应用发布后创建，效果时长结束或被新事件替换时销毁。
- 持久化位置：无。
- 是否需要迁移：否。

## 修改范围

### 计划修改

- `app/systemMoments.ts`：定义事件契约及发布、订阅函数。
- `src/shell/DesktopMomentLayer.tsx`：渲染三类一次性桌面效果。
- `src/shell/DesktopRoot.tsx`：订阅事件并管理当前瞬时效果。
- `app/desktop.css`：增加系统效果层样式与减少动态效果规则。
- `src/apps/photo/entry.tsx`：在另存新图片成功分支发布创作事件。
- `src/apps/drawing/entry.tsx`：在保存新图片成功分支发布创作事件。
- `src/apps/focus/entry.tsx`：在专注模式自然完成分支发布专注事件。
- `src/apps/mines/entry.tsx`：在用户胜利分支发布游戏事件。
- `src/apps/chess/entry.tsx`：在用户胜利分支发布游戏事件。
- `src/apps/gomoku/entry.tsx`：在用户胜利分支发布游戏事件。

- 直接相关的应用单测：覆盖每个来源只在表格规定的条件下发布事件。
- `docs/iterations/`：按本 Spec 拆分并记录单目标实施结果。

### 不修改边界

- 保持游戏胜负、概率、难度、金币、战绩和存档行为不变。

- 保持桌面通知、Toast、音效设置和 `playNovaSound` 实现不变。
- 不接入魔塔、YouTD 2 和童年老虎机。
- 不新增持久化、配置页面、后台定时器或日期判断。
- 不新增兜底、成功复核、自动重试或跨窗口事件补发。

## 验收标准

- [x] AC-1：照片实验室另存新图片或画板保存新图片成功时，桌面显示一次 `creative-save` 效果；覆盖、失败或取消不显示。
- [x] AC-2：专注模式自然完成时，桌面显示一次 `focus-complete` 效果；手动停止、重置和其他计时模式不显示。
- [x] AC-3：扫雷、国际象棋或五子棋判定用户胜利时，桌面显示一次 `game-win` 效果；失败、和棋和重开不显示。
- [x] AC-4：效果播放期间，用户仍可点击、拖动、输入和切换窗口，焦点与窗口状态不发生变化。
- [x] AC-5：连续到达两个事件时，第二个效果替换第一个，不形成播放队列，效果结束后 DOM 被清理。
- [x] AC-6：启用减少动态效果时不出现粒子位移或循环动画，只显示短暂静态光晕。
- [x] AC-7：关闭系统音效时彩蛋无声音；开启时只复用一次现有成功音效。
- [x] AC-8：刷新页面后不补播事件，备份内容和本地存储项数量不因彩蛋能力变化。
- [x] AC-9：三个游戏和三个创作/专注应用的原有保存、计时、结算、存档与错误处理保持不变。

## 风险与迁移

- 已知风险：应用成功分支目前分散，接入时必须只增加事件发布，避免顺手统一或重构完成逻辑。
- 已知风险：桌面效果层的层级若设置不当可能遮挡菜单或窗口操作，需要通过 `pointer-events` 和层级测试验证。
- 已知风险：国际象棋和五子棋的人机双方均可能获胜，事件必须只绑定现有“用户胜利”结果。
- 数据迁移：无。
- 回滚方式：移除各应用发布调用和桌面订阅/效果层；不会留下需要清理的数据。

## 待确认项

- 是否接受首版只包含“创作保存、专注完成、三款棋盘/解谜游戏胜利”三类事件。
- 是否接受照片实验室只有“另存为新图片”触发彩蛋，覆盖原图不触发。
- 是否接受首版彩蛋是瞬时视觉反馈，不生成永久纪念物，也不保存发现记录。
- 是否接受同一时刻新彩蛋直接替换旧彩蛋，不排队播放。

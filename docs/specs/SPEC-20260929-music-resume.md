# SPEC-20260929：接着听上次的音乐

- 状态：已完成
- 提出日期：2026-09-29
- 相关 ADR：`docs/adrs/ADR-0009-music-playback-bookmark.md`
- 相关迭代：`docs/iterations/ITER-20260929-music-resume-01.md`

## 背景与目标

用户明确 NOVA 是自己看小说、听喜欢的音乐和放松的个人空间，撤回工作集、跨应用工作流、内容关联和任务内 AI 路线。本批只补一个日常体验断点：重新打开音乐后，主动点击即可接着听上次的歌曲。

阅读器 `src/apps/reader/entry.tsx` 已根据阅读记录提供“继续阅读”，本轮不重复建设。音乐 `usePlayer.ts` 的歌曲、时间和队列仅存在组件内，关闭窗口后丢失；`listeningHistory.ts` 保存按天累计时长，不能表示上次播放位置。

## 用户可感知行为

- 音乐“我的音乐”页显示上次歌曲、歌手、听到的位置与“继续听”按钮；没有播放记录时不显示。
- 点击后从记录位置播放该曲，并保留原播放队列和现有播放模式。读库和打开窗口不启动音频或音效。
- 当前窗口已选择歌曲后，由原播放器负责继续/暂停，不同时显示过期的续听入口。
- 完整播完的歌曲不从末尾立即跳走，续听从该曲开头开始。
- 删除上次歌曲时删除对应续听记录；删除队列中其他歌曲时移除其引用；已有音频去重同步更新记录引用。
- 续听记录随现有音乐备份导出、恢复和清理，不复制音频或增加云服务。

## 技术方案与状态归属

- 在 IndexedDB `nova-music` 已有 `settings` 对象仓库增加可选 `playback` 记录，包含歌曲 ID、秒数和队列 ID。曲库返回值带此记录。
- 不更改数据库版本，不迁移旧数据；从未播放或没有续听记录的曲库保持无记录状态。
- 复用现有播放器媒体事件：实际开始播放、现有 15 秒听歌记录提交、暂停、跳转完成、关闭和 pagehide 时记录位置。不增加定时器或后台运行任务。
- 恢复位置由媒体元数据加载事件完成；主动点击沿用现有 AudioContext/play 调用。普通选歌、分享歌曲、演出启动仍按原逻辑播放，不读取续听位置。
- 新记录持久化错误沿用播放器现有 onError 提示通道；不增加重试、备用存储、提交前复核或新的确认流程。

## 修改范围与边界

- 音乐 model、storage、storageProvider、usePlayer、entry、music.css：续听数据、生命周期、按钮和自适应展示。
- 独立的续听媒体事件辅助模块及相关单测：验证延迟元数据、切歌及持久化生命周期。
- README、Spec、迭代记录、ADR 与 Service Worker 版本号：交付记录和版本更新提示；不改变缓存策略。
- 不修改阅读器、桌面外壳、文件模型、应用窗口生命周期、听歌统计口径、下载时机、AI 或现有分享自动播放行为。
- 不恢复演出编排、舞台、音效、页面或其他应用窗口，不新增最近播放列表、推荐系统或工作集。

## 验收标准

- [x] AC-1：首次打开无续听记录；播放并暂停或关闭后再打开，能看到准确曲目与位置，点击前不播放。
- [x] AC-2：主动点击后恢复位置与队列，下一首沿用原队列；普通选歌不套用旧位置。
- [x] AC-3：加载元数据较慢或用户快速切歌时，旧续听位置不影响新歌；播完歌曲从头续听。
- [x] AC-4：记录随备份恢复和清理；删除歌曲、队列变化及音频去重后引用一致；无记录的旧曲库正常打开。
- [x] AC-5：桌面与窄屏入口可用，刷新桌面不自动打开应用，不自动播放。
- [x] AC-6：TypeScript、直接相关单测、隔离浏览器最短关键路径与 diff 审查通过。

## 验证计划与风险

- `npx tsc --noEmit --incremental false`；音乐续听、存储、听歌统计、媒体控制、分享与演出相关单测。
- 隔离浏览器中用测试音频直达“播放 → 定位 → 关闭 → 重开 → 继续听 → 下一首”，并检查窄屏布局。
- 不运行 lint 或完整构建；提交钩子照常执行。不改真实浏览器用户数据，不手动发布。
- 浏览器强制终止时最后一次未完成的异步写入可能丢失；依赖实际播放期间已有提交节奏，不新增持久化兜底。

## 背景与问题

当前仓库中的 `frontline` 仅是用于证明接入链路的 DOM 原型。它复用了少量背景和角色单帧，但与参考游戏存在结构性差异：

- 单位只是静态 PNG，没有待机、行走、攻击、受击、死亡、召唤和技能动画；
- 没有原版 Spine 骨骼、粒子、材质、投射物、飘字和音效的组合播放；
- 塔位、路径、角色尺寸、遮挡关系和镜头节奏与原版不一致；
- 战斗数值是原型参数，不是依据原游戏行为采样得到的配置；
- UI 使用文字、emoji 和 CSS 形状代替原版图集；
- 章节地图与战斗之间只有功能跳转，没有原版进入、结算和解锁演出。

本 Spec 用于替换该原型。最终目标不是“同类型塔防”，而是在不接入原游戏服务器的前提下，以本机可读取的原版美术资源和现场行为为基准，完成观感、节奏和操作结构基本 1:1 的本地战斗版本。

## 产品目标

### 核心目标

1. 在 NOVA 游戏大厅中保留一个独立的《王国大作战：前线》窗口。
2. 复刻参考客户端的主线地图、开始挑战、战斗、暂停和结算闭环。
3. 使用原 Unity AssetBundle 中的地图、Spine 角色、战斗 UI、特效和音频资源。
4. 完整表现单位生命周期和攻击反馈，不使用静态单帧代替战斗动画。
5. 先完整复刻第一关并将其沉淀为数据驱动的关卡模板，再按原版顺序逐关扩展，不以三个关卡或任意 Demo 数量作为完成边界。
6. 保持完全本地运行；刷新后保留关卡星级和解锁进度。
7. 桌面启动时不加载本游戏资源，打开游戏后才加载独立资源包。

### 高保真定义

“基本 1:1”在本项目中指：

- 同一参考关卡的地图构图、路线、塔位、出生门和水晶位置一致；
- 同一单位的外形、朝向、缩放、锚点和动画状态来自原资源；
- 波次、出怪顺序、移动节奏、攻击间隔、投射物节奏和伤害反馈以行为采样结果为准；
- 战斗 HUD 的区域、层级、按钮图形、数值位置和状态变化与参考客户端一致；
- 召唤、强化、领主技能、暂停、倍速、胜利和失败的交互顺序一致；
- 在 900×1600 参考画布上进行像素级对照时，主要 UI 边界和战场锚点允许误差不超过 6px；
- 动画关键事件的时序误差不超过 80ms，单位移动到同一路径采样点的误差不超过参考画布 8px。

高保真不要求联网经济、商业活动或服务器数值一致。

### 提取产物

新增确定性离线提取脚本，输入固定版本 AssetBundle，输出：

```text
public/assets/games/frontline/
  manifest.json
  maps/
  spine/
    <actor>/skeleton.skel
    <actor>/skeleton.atlas
    <actor>/texture.png
  sprites/
  effects/
  audio/
  ui/
```

`manifest.json` 必须记录：

- 源 Bundle 文件名和 SHA-256；
- 输出文件 SHA-256；
- Spine 资源版本、缩放和默认皮肤；
- 每个角色可用动画名；
- Sprite 原始矩形、pivot、border 和 pixels-per-unit；
- AudioClip 名称、时长和输出格式；
- 原 Unity 材质到 Web 渲染实现的映射。

禁止：

- 从截图裁剪角色或 UI；
- 只导出 Spine 图集中的一帧充当单位；
- 将源图重新绘制成 emoji、CSS 图形或通用图标；
- 把 119MB 全量资源无选择地放入仓库；
- 在资源不存在时自动使用替代素材。

### Spine 转换

首选方案是在 Web 运行时直接加载原 `.skel + .atlas + texture`，保留骨骼、slot、skin、颜色和事件轨道。实现前必须先识别二进制骨骼版本，并选择对应版本的 Spine Web runtime。

若原骨骼版本无法由允许使用的 runtime 读取，则在构建前将每个动画按固定帧率烘焙为图集：

- 待机、行走：24fps；
- 普攻、技能、受击、死亡、召唤：30fps；
- 保留原动画持续时间和事件帧；
- 图集使用透明 PNG/WebP，不裁掉武器、拖尾和越界特效；
- 生成包含帧矩形、pivot、时长、事件点的 JSON；
- 烘焙结果必须与原客户端逐帧抽样对照。

是否直读 Spine 或离线烘焙只允许在第一个资源迭代中确定一次；同一版本不能混用两套角色动画管线。

## 技术架构

### 模块边界

```text
src/apps/frontline/
  entry.tsx                 # 窗口入口、地图/战斗/结算场景切换
  frontline.css             # 窗口幕布和 DOM HUD 布局
  core/
    battleTypes.ts          # 战斗状态与配置类型
    battleReducer.ts        # 命令和状态归约
    fixedStepClock.ts       # 固定时间步、暂停与倍速
    path.ts                 # 路径采样、朝向和距离
    targeting.ts            # 索敌和攻击目标选择
    damage.ts               # 伤害、状态、死亡和奖励
    waves.ts                # 波次调度
    progression.ts          # 星级与关卡解锁
  content/
    levels.ts               # 关卡注册表，只负责顺序与按需查找
    levels/
      <level-id>.ts         # 单关地图、波次、单位和事件配置
    actors.ts               # 单位数值与动画映射
    skills.ts               # 技能配置
  renderer/
    BattleCanvas.tsx        # Canvas/WebGL 宿主
    BattleRenderer.ts       # 场景树、相机和排序
    ActorView.ts            # Spine/图集单位实例
    EffectView.ts           # 投射物、粒子、飘字
    ResourceLoader.ts       # 严格按 manifest 加载
  ui/
    WorldMap.tsx
    BattleHud.tsx
    PauseDialog.tsx
    ResultDialog.tsx
  storage.ts
  audio.ts
```

- React 只管理场景、弹窗和 HUD；逐帧单位状态不得进入 React state。
- 战斗模拟由纯 TypeScript 状态机运行。
- 战场单位、动画、特效和投射物统一由 Canvas/WebGL 场景树渲染。
- HUD 保持 DOM 渲染以支持无障碍和可靠按钮交互，但视觉必须使用原图集切片。
- 渲染器不读取 NOVA 窗口位置，只读取应用内容区尺寸。

### 时间模型

- 战斗模拟固定步长 `1 / 60s`；
- 渲染使用 `requestAnimationFrame` 并对前后状态插值；
- 单帧最多追赶 5 个模拟步，不把累计时差直接作为一次大步长；
- `×2` 通过每个显示帧执行两倍模拟步实现，不修改各单位动画配置；
- 暂停冻结模拟时钟、骨骼动画、粒子、投射物和音频事件；
- 页面不可见时停止 RAF，恢复时从零累计，不补算隐藏期间时间；
- `prefers-reduced-motion` 只关闭非战斗装饰动画，不得取消攻击、命中、死亡等玩法必要动画。

### 坐标、寻路和遮挡

- 每关配置一条按逻辑画布坐标定义的 Catmull-Rom 或等距折线路径；
- 从原地图可见道路中心线采样路径点，路径入口和出口与出生门、水晶锚点一致；
- 敌人按弧长而不是点索引匀速移动，转弯时朝向平滑切换；
- 领主在配置的战斗区域内接敌、攻击并返回锚点；
- 塔台使用原 Sprite pivot 对齐石台中心，不用图片边界居中；
- 场景按 `layer + footY` 排序：地图底层 → 地面特效 → 石台 → 单位 → 空中特效 → 飘字 → HUD；
- 飞行投射物不参与 footY 排序，使用独立空中层；
- 首领体型不改变路径碰撞中心，只改变渲染尺寸和受击框。

## 战斗状态模型

```ts
type BattlePhase =
  | "loading"
  | "intro"
  | "wave-countdown"
  | "fighting"
  | "wave-clear"
  | "boss-intro"
  | "paused"
  | "victory"
  | "defeat";

type ActorState =
  | "spawn"
  | "idle"
  | "move"
  | "windup"
  | "attack"
  | "recover"
  | "hurt"
  | "skill"
  | "death";

type BattleState = {
  phase: BattlePhase;
  levelId: string;
  tick: number;
  speed: 1 | 2;
  waveIndex: number;
  killed: number;
  totalEnemies: number;
  baseHp: number;
  coins: number;
  essence: number;
  globalUpgradeLevel: number;
  summonCount: number;
  summonLimit: number;
  actors: Record<string, ActorModel>;
  projectiles: Record<string, ProjectileModel>;
  statuses: Record<string, StatusEffect[]>;
  queuedEvents: BattleEvent[];

```

所有玩家操作转换为封闭命令：

```ts
type BattleCommand =
  | { type: "toggle-pause" }
  | { type: "set-speed"; speed: 1 | 2 }
  | { type: "summon" }
  | { type: "upgrade-all" }
  | { type: "cast-skill"; skillId: string }
  | { type: "exit" };
```

渲染器只消费状态和 `BattleEvent`，不自行判定伤害、金币或胜负。

## 单位与动画规范

### 动画状态机

每种单位必须提供以下状态映射。视觉表现必须来自已验证的原骨骼动画、材质或独立特效；禁止为了补齐状态名而伪造 Spine 动画：

| 状态 | 循环 | 可被打断 | 切换规则 |
| --- | --- | --- | --- |
| `spawn` | 否 | 否 | 播放结束进入 `idle/move` |
| `idle` | 是 | 是 | 获得目标后进入 `windup` |
| `move` | 是 | 是 | 到达攻击范围进入 `windup` |
| `windup` | 否 | 特定技能可打断 | 到事件帧生成攻击事件 |
| `attack` | 否 | 否 | 事件帧生成投射物/命中，结束进入 `recover` |
| `recover` | 否 | 否 | 结束后重新索敌 |
| `hurt` | 否 | 是 | 播放源资源实际使用的受击材质/特效或骨骼动画，不改变已确认的死亡结果 |
| `skill` | 否 | 否 | 事件帧触发技能效果 |
| `death` | 否 | 否 | 播放结束后移除显示对象 |

### 朝向

- 原资源为单向侧视时，使用 `scaleX = ±1` 水平翻转；
- 角色根据目标相对 X 方向切换朝向；
- 朝向切换只发生在移动开始、锁定目标或攻击恢复结束时，不在攻击动作中途翻转；
- UI 头像和图鉴立绘不得跟随战场朝向翻转。

### 攻击事件

动画必须通过事件帧驱动战斗表现：

1. `windup-start`：播放起手音效；
2. `projectile-spawn` 或 `hit-frame`：创建投射物或结算近战命中；
3. `muzzle-flash`：播放武器/法术发射特效；
4. `hit`：播放目标受击、伤害飘字和命中特效；
5. `recover-end`：允许下一次索敌。

禁止在动画开始瞬间直接扣血后再延迟播放视觉效果。

源 Spine 没有事件轨时，必须从同版本 Lua/MonoBehaviour 配置或固定录像逐帧采样得到事件时点，并写入 Manifest 的显式时序元数据。该元数据视为原动画的外部事件轨，仍由动画播放时间驱动；禁止把主观估计伪装成 Spine 内置事件。

### 第一章源资源例外

- 已确认 `char_monster_01_*` 五个怪物均只提供 `stand`、`run`、`attack_1`、`dead`，没有独立 `hurt` 骨骼动画；
- 第一章怪物 Spine 资源没有动画事件轨；
- 因此第一章怪物的 `hurt` 为战斗语义状态，视觉必须复用原客户端实际的材质闪色、命中特效和伤害飘字，不新增假骨骼动画；
- `attack_1` 的命中时点必须在后续迭代通过同版本配置或逐帧行为采样锁定，时序误差仍不得超过 80ms。

### 完整动画清单

- 敌人：出生、行走、普攻、源资源受击反馈、死亡；
- 远程敌人：额外包含投射物生成和命中；
- 首领：出生镜头、待机、行走、普攻、技能、受击、死亡；
- 防御单位：召唤、待机、普攻、技能/强化响应；
- 领主：待机、跑向目标、普攻连段、受击、返回锚点；
- 水晶：待机、受击闪烁、低生命状态、破碎；
- 石台：空台、召唤光柱、单位落位、强化光圈；
- UI：按钮按下、资源变化、技能次数变化、波次切换、首领提示、胜负面板。

## 战斗规则

### 波次

- 关卡配置显式列出每波敌人类型、数量、间隔、组间停顿和首领位置；
- 第一只敌人出现前播放波次倒计时；
- 当前波全部生成且场上敌人清空后进入 `wave-clear`；
- 波次切换期间单位保持待机，资源结算完成后开始下一波；
- 第六波首领生成前播放红色首领横幅和镜头轻微震动；
- 不根据设备帧率调整刷怪数量或间隔。

### 索敌

- 防御单位默认攻击“路径进度最高且在射程内”的敌人；
- 若原行为采样显示某单位使用最近、最低生命或特定标签优先，则写入该单位配置；
- 目标死亡或离开射程后在恢复结束时重新索敌；
- 范围攻击以命中点为圆心筛选目标；
- 领主只选择其防守区域内的敌人，不穿过地图障碍追击。

### 召唤与强化

- “召唤”只在资源足够且未达到当前上限时可用；
- 点击后立即扣除银币，播放按钮按下、召唤法阵、单位落位和石台反馈；
- 召唤结果、费用曲线、单位池和上限从行为采样表配置，不在组件内硬编码；
- “强化”消耗蓝色资源并作用于当前及之后召唤的防御单位；
- 强化完成时每个已有单位播放强化光柱，HUD 战力值同步跳字；
- 资源不足时保留原版禁用态和点击反馈，不增加自定义弹窗。

### 技能

每个关卡按参考战斗实际配置接入右侧主动技能；第一关当前观察到两个：

- 范围伤害技能：播放施法前摇、地面指示、落点特效、屏幕震动、伤害和受击；
- 控场技能：播放护盾/冲击视觉，对命中敌人施加参考行为对应的减速、击退或定身效果。

技能次数、目标选择、效果持续时间和能否对首领生效均以采样配置为准。技能从点击到生效之间必须经过动画事件，不允许瞬时修改所有敌人数值。

### 胜负与星级

- 敌人到达路径终点后攻击/撞击水晶，并在命中事件帧扣除基地生命；
- 基地生命归零立即进入失败演出，停止刷怪和玩家命令；
- 最后一波最后一个敌人死亡后进入胜利演出；
- 星级规则逐关按原版行为采样并固化到关卡配置，不设置跨关卡的猜测默认值；
- 结算确认后写入最高星级并解锁下一关；
- 中途退出不记胜负，不发放星级，也不保留当前战斗现场。

## UI 与场景演出

### 章节地图

- 使用 `Main_background_01` 原图作为第一章背景；
- 关卡节点使用原主线节点、旗帜、星级和选中光效；
- 当前节点显示关卡编号、已获星级和选中动画；
- 未解锁节点使用原锁定态；
- 底部挑战面板使用原按钮图，不使用 CSS 渐变按钮；
- 点击挑战后播放按钮压下、面板收起、地图淡出和战斗资源加载。

### 战斗 HUD

HUD 必须从 `gui_fight` 与 `gui_tex_fight` 还原：

- 顶部：关卡标题、波次、星级/击杀进度、首领条；
- 左侧：暂停、倍速、统计；
- 右侧：技能图标、次数和冷却遮罩；
- 底部：强化按钮、资源区、召唤按钮、召唤数量；
- 中央提示：怪物狂暴、波次开始、首领来袭、资源不足；
- 战场反馈：生命条、状态图标、伤害/暴击/治疗飘字。

DOM 按钮必须保留准确 `aria-label`。纯装饰图层不进入可访问树。

### 镜头与震动

- 进入关卡：地图淡入，出生门到水晶的短镜头巡视，然后回到默认视角；
- 首领登场：镜头聚焦出生门 0.6–0.9 秒，播放横幅后恢复；
- 重击：仅战场画布短促震动，HUD 不随镜头移动；
- 水晶受击：镜头向水晶方向轻移并叠加红色暗角；
- 胜利：时间短暂减速，最后一个敌人死亡完成后显示结算；
- 失败：水晶破碎播放完成后显示失败面板。

## 音频规范

- BGM、环境音和战斗音效分为三个通道；
- 使用原资源导出的 AudioClip，不使用浏览器系统音或 NOVA 通用提示音代替战斗音效；
- 相同普攻音效设置最小重叠间隔，规则写入单位配置；
- 倍速只改变音效触发节奏，不对音频做音高拉伸；
- 暂停时暂停 BGM 和循环环境音，已开始的一次性短音效停止；
- 游戏关闭时释放全部 AudioBuffer、Spine 实例和 RAF；
- NOVA 全局静音设置继续作为总开关。

## 数据与本地存档

```ts
type FrontlineProgress = {
  version: 1;
  sourceVersion: string;
  unlockedLevelId: string;
  completedLevelIds: string[];
  stars: Record<string, 0 | 1 | 2 | 3>;
  bestBaseHp: Record<string, number>;

```

- 不保存逐帧战斗现场；
- 开始关卡、暂停和窗口最小化不写入进度；
- 结算确认后一次性保存星级和解锁状态；
- “新开游戏”清除该游戏进度并恢复第一关；
- 全局游戏数据重置继续通过现有游戏 Storage Provider 覆盖本游戏；
- 不新增第二套 localStorage 或 IndexedDB 缓存。

## 性能目标

- 桌面参考设备在 900×1600 逻辑画布、DPR 2 下保持 60fps；
- 同屏支持至少 30 个敌人、8 个防御单位、1 个领主、40 个投射物和 80 个短生命周期特效；
- 单次模拟更新 P95 小于 4ms，单次渲染 P95 小于 10ms；
- 单位、投射物、飘字和粒子使用对象池，不在战斗中频繁创建 DOM；
- 战斗期间不得因 React 每帧 setState 引发组件树重渲染；
- 首次打开只加载章节地图所需资源，进入关卡再加载该关战斗包；
- 关闭窗口后释放内存但不删除 Cache Storage 中的按需资源。

## 测试方案

### 纯逻辑单测

- 固定 seed 下波次和召唤结果可重复；
- 固定 60Hz 与不同显示帧率下得到相同战斗结果；
- `×1` 和 `×2` 的模拟 tick 比例正确；
- 暂停期间 tick、动画事件和资源均不变化；
- 索敌、射程、投射物命中、范围伤害和死亡奖励正确；
- 敌人抵达终点只扣一次基地生命；
- 最后一波正确进入胜利，基地归零正确进入失败；
- 星级和关卡解锁只在结算确认后持久化。

### 资源契约测试

- `manifest.json` 中每个 SHA-256 与实际文件一致；
- 每个已实现关卡引用的单位均存在源资源实际提供的动画与完整生命周期映射；
- 每个动画事件引用的音效和特效均存在；
- UI Atlas 中必需 Sprite 均能按原 pivot 和 border 解析；
- 资源缺失时测试直接失败，不进入运行时占位分支。

## 已知实施风险

1. Spine `.skel` 版本必须与 Web runtime 匹配；版本不匹配会导致动画或事件轨道错误。
2. Unity 粒子不能直接在浏览器运行，需要按材质、发射、生命周期和混合模式逐项转换。
3. 固定版本 RKT 尾段与嵌套 DBC 已可确定性解析，第一关波次和刷怪配置已提取；RKT 私有前导后的 16384 字节保护算法仍需在读取首条目时继续逆向，禁止用录像推测替代已可读取的配置。
4. 原 UI 使用 SpriteAtlas 的九宫格、pivot 和边框信息；只导出裁剪 PNG 会造成按钮和面板比例失真。
5. 视觉 1:1 依赖统一参考版本；微信小游戏更新后不得混用新版资源与旧版行为基线。

这些风险需要在对应迭代中显式解决，不增加静默兜底、替代素材或第二套渲染路径。

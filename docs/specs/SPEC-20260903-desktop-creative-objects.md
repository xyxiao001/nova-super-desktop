# SPEC-20260903：创作结果桌面物件化

- 状态：已完成
- 提出日期：2026-09-03
- 负责人：Codex
- 相关 ADR：无
- 相关迭代：`docs/iterations/ITER-20260903-desktop-creative-objects-01.md`

## 背景

NOVA 的照片实验室、画板、阅读摘录和记事本已经能够把创作结果保存为统一的 `DesktopItem` 图片或文本文稿。保存后的内容会作为普通文件图标出现在桌面或文件夹中，可由照片、记事本和文件资源管理器继续打开。

当前桌面只为应用入口和文件提供统一尺寸的图标表现。照片、涂鸦和文字摘录虽然已经成为桌面文件，但无法像拍立得、便笺等物件一样直接参与桌面布置，创作结果对桌面环境本身没有持续影响。

本项目主要供单人使用，本 Spec 优先增强个人表达和摆放乐趣，不追求通用桌面组件平台或可扩展组件市场。

## 目标

用户可以把现有的图片文件显示为“照片卡片”，把现有的文本文稿显示为“文字便笺”，在桌面上自由摆放，并可随时恢复为普通文件图标；桌面物件始终引用原始 `DesktopItem`，不复制创作内容、不新增文件类型，原文件仍由现有应用编辑、备份和管理。

## 非目标

- 本次不实现天气、时钟、待办等通用桌面小组件。
- 本次不实现物件商店、主题包、成就奖励或在线素材。
- 本次不实现任意缩放、任意旋转、颜色选择、字体选择或物件模板编辑器。
- 本次不把文件内容复制到新的私有存储，也不新增 `DesktopItem` 类型。
- 本次不改变照片实验室、画板、阅读器和记事本现有的保存时机、保存参数及异常处理。
- 本次不改变文件夹层级、文件打开方式、回收站和文件冲突处理规则。

## 当前行为

- 桌面文件由 `DesktopRoot` 加载并通过 `nova-desktop` IndexedDB 保存，文件类型限定为文件夹、文本和图片。
- 顶层文件由 `DesktopFile` 统一渲染为文件图标；图片图标显示缩略图，文本文稿显示 `TXT` 图标。
- 桌面应用入口和顶层文件共享 `nova-desktop-positions` 布局数据，并按照图标槽位重新排序。
- 文件右键菜单提供打开、打开方式、重命名、下载、剪切、复制和删除等操作。
- 文件移入回收站后不再出现在桌面；还原后重新出现；永久删除会同时删除其桌面位置。
- 桌面文件由 `desktop` Storage Provider 参与备份、恢复和清理，桌面图标位置由 `settings` Storage Provider 管理。

## 方案

### 用户可感知行为

- 单选一个图片文件时，桌面右键菜单增加“显示为照片卡片”。
- 单选一个文本文稿时，桌面右键菜单增加“显示为文字便笺”。
- 转换只改变该文件在桌面上的表现，不创建副本、不修改文件名和内容。
- 照片卡片显示图片预览和文件名；文字便笺显示文件名和正文开头的有限摘要。
- 桌面物件使用一套固定尺寸和固定视觉样式，不在首版提供样式配置。
- 桌面物件可以在桌面有效区域内自由拖动，不参与普通图标的槽位排序，也不会把相邻图标推开。
- 双击桌面物件时，沿用原文件现有的默认打开方式；右键菜单保留原有文件操作，并增加“恢复为文件图标”。
- 将源文件移入回收站后，对应桌面物件不显示；还原文件后恢复为此前的物件表现和位置。
- 永久删除源文件后，同时删除其物件表现和位置元数据。
- 将源文件移动到文件夹后，桌面物件仍保留，作为指向该文件的桌面陈列入口；“恢复为文件图标”后，由于源文件不在桌面根目录，不再显示该文件。
- 紧凑视口显示桌面物件，但按现有移动端桌面交互采用长按进入菜单、单击打开；首版不支持在紧凑视口拖动物件。

### 技术设计

- 新增桌面物件表现模型，首版只包含：
  - `photo-card`：仅允许引用 `DesktopItem.type === "image"`；
  - `note-card`：仅允许引用 `DesktopItem.type === "text"`。
- 每条表现记录以源文件 `itemId` 为唯一键，保存 `kind`、桌面坐标和创建时间；一个文件最多对应一个桌面物件。
- 表现记录与文件内容分离：渲染时从当前工作区按 `itemId` 读取名称、图片内容或文本摘要。
- 新增独立的桌面物件渲染组件；普通文件图标、应用快捷方式及其排序逻辑保持现状。
- 桌面物件拖动使用指针坐标并限制在桌面可见区域；拖动结束时写入新的物件坐标。
- 普通文件转换为物件后，从普通文件图标列表中排除，但不改变文件的 `parentId`。
- 文件回收、还原、移动和内容编辑不主动修改物件记录；渲染层依据源文件当前可见性和内容派生显示结果。
- 永久删除文件时，沿用当前删除结果中的 `removedIds` 清除对应物件记录。
- 不建立通用插件式物件注册表；首版使用封闭联合类型实现两种表现。

### 数据与状态归属

- 数据所有者：桌面外壳，只拥有文件的表现类型和摆放坐标；文件内容仍归统一桌面工作区。
- 状态生命周期：转换为物件时创建，恢复为图标或永久删除源文件时删除。
- 持久化位置：`localStorage` 键 `nova-desktop-objects`。
- 备份与清理：该键明确归入 `settings` Storage Provider，与桌面位置一起导出、恢复和清理。
- 是否需要迁移：否；现有用户没有该键，缺少记录时所有文件继续按普通图标显示。

## 修改范围

### 计划修改

- `app/desktopObjects.ts`：定义桌面物件类型、读取写入和纯函数操作。
- `app/desktop.css`：增加照片卡片、文字便笺及其交互样式。
- `src/shell/DesktopCreativeObjects.tsx`：渲染和操作桌面物件。
- `src/shell/DesktopRoot.tsx`：加载物件状态、接入右键菜单、文件打开和永久删除联动。
- `src/platform/storage/providers/localSettings.ts`：将物件布局键归入桌面设置数据。
- `tests/unit/desktopObjects.test.ts`：覆盖转换、恢复、可见性和删除联动。
- `tests/unit/storageProviders.test.ts`：覆盖新键的 Storage Provider 分类。
- `docs/iterations/`：按本 Spec 拆分并记录单目标实施结果。

### 不修改边界

- 保持 `DesktopItem` 类型、字段和 IndexedDB 数据结构不变。
- 保持创作应用现有保存行为和工作区命令不变。
- 保持普通桌面图标的排序、拖放和位置数据不变。
- 保持文件夹、资源管理器、回收站、备份版本和恢复流程不变。
- 不新增兜底、自动重试、兼容分支或内容副本。
- 不引入图片、SVG、图标或第三方拖拽依赖。

## 验收标准

- [x] AC-1：给定桌面上的图片文件，当选择“显示为照片卡片”时，桌面显示引用该图片的固定样式卡片，原文件数据不变且不产生新文件。
- [x] AC-2：给定桌面上的文本文稿，当选择“显示为文字便笺”时，桌面显示名称和正文摘要，原文件数据不变且不产生新文件。
- [x] AC-3：给定一个桌面物件，当在宽屏桌面拖动并释放时，新坐标被保存，刷新后位置保持。
- [x] AC-4：给定一个桌面物件，当双击时，图片或文本沿用现有默认应用打开。
- [x] AC-5：给定一个桌面物件，当选择“恢复为文件图标”时，物件记录被删除；根目录文件恢复为普通图标。
- [x] AC-6：给定一个已物件化文件，当移入回收站、还原和永久删除时，分别表现为暂时隐藏、恢复原物件和永久移除物件记录。
- [x] AC-7：给定一个已物件化文件，当移动到文件夹时，桌面物件继续显示并能打开该文件；恢复为图标后不再显示在桌面根目录。
- [x] AC-8：备份导出包含桌面物件布局，恢复备份后物件表现和位置恢复；清除桌面设置后文件仍保留但恢复为普通表现。
- [x] AC-9：普通应用快捷方式和未物件化文件的排序、拖放、打开及右键菜单行为保持不变。

## 风险与迁移

- 已知风险：桌面物件与普通图标使用不同定位方式，需要确保物件不会覆盖任务栏且不会触发普通图标重排。
- 已知风险：源文本可能很长，摘要必须在渲染时截断，不能复制全文到物件记录。
- 数据迁移：无。
- 回滚方式：移除物件渲染和菜单入口；删除 `nova-desktop-objects` 后所有源文件仍按现有文件模型保留。

## 待确认项

- 是否接受首版只支持照片卡片和文字便笺，不包含画板专用贴纸样式；画板保存的图片仍可转换为照片卡片。
- 是否接受物件使用固定尺寸和样式，首版不提供缩放、旋转和换色。
- 是否接受物件化文件移动到文件夹后仍作为桌面陈列入口保留。
- 是否接受紧凑视口首版只显示和打开物件，不支持拖动摆放。

# SPEC-20260917：全局搜索直达文稿命中位置

- 状态：已完成
- 提出日期：2026-09-17
- 相关 ADR：无
- 相关迭代：`docs/iterations/ITER-20260917-note-search-location-01.md`

## 背景

当前全局搜索已扫描文本文稿正文，但搜索结果只显示“文本文稿 · 打开所在位置”，点击后进入文件资源管理器，而不是打开文稿和定位命中内容。记事本自己的搜索也只筛选文稿，没有承接来自全局搜索的定位意图。

## 目标

正文命中时显示围绕首个匹配位置的单行片段；点击结果直接打开对应记事本文稿，并选中首个匹配文字。文件名命中仍直接打开文稿，但不制造正文定位。

## 非目标与边界

- 不新增全文索引、数据库、Worker、搜索历史、模糊搜索或排序评分。
- 不改变应用、书籍、设置和系统结果的现有搜索与打开行为。
- 不改变资源管理器搜索、记事本侧栏搜索、文件内容、备份或存储模型。
- 不处理图片 OCR、书籍正文、回收站或已删除文件。
- 不增加自动重试、兼容分支、Markdown、AI 或新应用。
- 不提交、推送、构建或发布。

## 用户可感知行为

- 文稿正文命中：结果副文案为命中片段，查询词两侧最多保留有限上下文；换行折叠为空格。
- 文稿名称和正文同时命中：仍显示正文命中片段并定位首个正文命中。
- 仅名称命中：显示“文本文稿 · 打开文稿”，打开文稿但不定位正文。
- 点击正文结果：打开或聚焦该文稿的记事本窗口，选中首个不区分大小写的精确匹配，并使其可见。
- 定位意图仅作用于目标文稿和本次请求，不改变正文或当前搜索框。

## 技术设计

- 新增纯函数计算首个不区分大小写的匹配范围和紧凑片段；不持久化索引。
- `AppLaunchTarget` 为 notes 增加可选 selection，沿用已有 LaunchRuntime 请求与确认机制。
- 记事本消费定位意图，在 textarea 挂载或文稿切换后调用原生 selection API 和 scrollIntoView 等价能力；定位失败则正常打开文稿，不提示虚假成功。
- 全局搜索直接打开 notes 的 per-resource 窗口，不再把文本结果路由到资源管理器。

## 验收标准

- [x] AC-1：正文匹配返回正确范围和规范化片段；大小写匹配、边界截断和换行均有测试。
- [x] AC-2：文本搜索结果点击后打开目标文稿，传递首个正文匹配范围。
- [x] AC-3：记事本接收当前文稿定位意图后选中目标文字；新请求可以重复定位。
- [x] AC-4：仅文件名命中不产生正文选区；非文本结果的现有行为保持。
- [x] AC-5：TypeScript、相关单测、浏览器最短路径和 diff 审计通过。

## 风险

React 受控 textarea 可能在定位前重新渲染，因此定位必须发生在目标文稿渲染完成之后，并以请求 ID 防止重复执行。搜索片段只用于展示，不作为定位的权威来源；定位使用原始正文范围。
